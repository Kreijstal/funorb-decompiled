# GeoBlox pass 13: interface text and decoder roles

Pass 13 retains all 642 prior rules and adds 199 guarded names. The complete
manifest has 841 rules: 18 classes, 346 fields, 136 methods, 103 parameters and
238 locals. The raw 303-file Java tree and decompiler revision are unchanged.
The readable mirror is generated from the same pinned raw source with the
reviewed additions and updated, frozen naming validator.

## Direct resource evidence

The original `wi.a(BLrh;)V` reads 744 resource keys. Of those reads, 218 directly
assign decoded strings to 152 fields, including indexed text arrays. One field,
`Geoblox.field_z` (`reconnectMessages`), already has a reviewed name. The other
151 fields receive names from their explicit resource keys. The evidence
includes the enclosing class's unqualified `field_F` assignment for
`loading_graphics`, as well as qualified field and array assignments.

The [text manifest](https://github.com/Kreijstal/funorb-decompiled/blob/29baf97271daba9862060eece24bc6e4cb0b11c0/readable/rules/geoblox-v13-text.json) records every destination's
original field identity, spelling, key, array index and source line. The
[evidence check](text-resource-evidence.mjs) compares that record with the pinned
loader bytes and checks every destination against the retained and new rules.
It rejects mismatched keys, missing destinations, changed array positions,
stale source, spelling guards and changed prior names. The 526 other reads
discard the decoded result; no destination field is invented for them.

For example, the generated loader contains:

```java
textResourceBytes = fk.readTextResourceBytes(2229, "loading_music");
if (textResourceBytes != null) {
  dd.loadingMusicText = ag.decodeTextBytes(1, textResourceBytes);
}
```

The key, guard value, null test, decode and assignment remain identical in
behavior. The naming pass changes resolved identifiers only.

## Shared helpers and decoding

The carrier now names its resource bytes, archive, guard, flow-flag snapshot,
runtime failures and context builders. Its constructor arguments have the same
roles. `loadInterfaceTextPart1` through `Part3` describe consecutive size-budget
partitions, not invented semantic phases. Nineteen new rules identify carrier
fields, methods, parameters or carrier-related locals generated by the
decompiler; those identities are not original gamepack members.

`decodeTextSlice` names its byte index, output position, buffer aliases, decoded
length and mapped character values. Input bytes are unsigned; NUL is omitted;
values 128 through 159 use a fixed character table, with question marks for
zero entries. The code is not treated as UTF-8. Existing guard side effects,
arithmetic, resource keys, error-context strings and statement order remain.

## Generic naming-tool change

The old validator rejected parameter rules containing `<init>`, as though they
renamed a constructor method. The new validator permits resolved constructor
parameters while still rejecting method rules for constructor names. This
allows descriptive initialization parameters on the shared local carrier.

The adapted naming-tool commit is
`a0bc835957148b9b1e1f8221c59b79d899d22738`. Its repository source archive has
SHA-256 `cb10756aa3ecb28159c9b81f2fb78bf559b4111d9ad203819458b30d0d84cf8c`.
[The tool pin](tools/PIN.json) records that revision, archive and file hashes.
The Java resolver and binding/override checks are unchanged. Nine focused tool
tests pass, including overloaded constructors, field/parameter shadowing, a
local carrier, original-versus-renamed JVM execution and exact map reversal.
The old validator fails the new parameter fixture before emitting output.

The builder's 14 checks guard the complete historical lineage, retained
identities, new-rule uniqueness, spelling and reviewed tool/source pins. Seven
text-evidence checks cover all 152 destinations and negative key/index/source
cases. Both complete 303-file corpora compile. Javac compares 154,256 bindings
and 388 override relationships; the generator applies 15,595 identifier edits.
Exact regeneration and dictionary-only reversal preserve every source byte.

The text probe passes for raw and renamed sources and for the fixed transformed
bytecode when its optional class-directory argument is supplied. It covers four
whole-array inputs including all 256 byte values, 32 slice comparisons (31 distinct slices), decoder guard
effects, an empty null slice, the reader's rejected guard and the nested context
of a null-archive failure. Successful archive loading and all panel interactions
remain outside this probe's scope. Deque and gameplay helper checks also pass
for both source variants.
